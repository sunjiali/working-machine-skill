# Working Machine Skill

把任何问题做成一台**可交互的「working machine」**：不写「关于 X 的文章」，而是造一台 X 本身——用户点着步骤把它运行起来、在做功的部位开剖切窗看因果、拖滑杆亲手把它「搞坏」。一台机器 = 一个独立页面（3D 默认 Vite + React + React Three Fiber 模块化工程，构建为纯静态站），全部数字由同一个纯函数小模型驱动。

这是一个给 AI agent 用的生产 skill：从选题、模型、建模、真机参考、视觉定式，一路管到**产品级质量门验收、60 秒演示录制与部署上线**。整机（一台服务器、一台意式机）与单个元件（一个继电器、一颗传感器）共用同一套壳与标准。

## 先看成品

用本 skill 做出的两台机器（公开站，点开就能玩）：

- **服务器硬件课**（整机级 · 3D）：https://sunjiali.github.io/working-machine-courses/
  2U 服务器整机：6 步开机时序导览、7 个部件热点、实验室（负载/室温/风扇故障）、RAID 拔盘降级—重建状态机、6 节课、分解视图与可拖拽部件、进度持久化。
- **继电器元件课**（元件级 · 2D 剖面）：https://sunjiali.github.io/working-machine-courses/relay/
  一个继电器的内部因果链：小电流 → 磁场 → 衔铁 → 触点 → 大电流负载；3 个故障场景（触点粘连/线圈烧断/弹簧疲劳）、互动题、常闭触点对比视图、自动演示入口。

## 方法骨架

1. **先凑输入**：一个问题（不是品类名）+ 一句「待证明的事实」（元件级换成「最容易被误解的一点」）+ 查证过的数字 + 真机参考清单。
2. **机器六件套**：本体、步骤按钮（只放行下一步）、剖切窗、一个模型驱动全部数字、长在动作上的文字、一句 big idea；外加默认做的「搞坏它」实验室。
3. **模型先行**：先写纯函数模型并**锁定回归基线**，再画图；每组改动后实机回读核对，基线不变才算过。
4. **渲染质感基线**：阴影、环境反射、ACES 色调映射、有边界的场景台面、默认机位主体占比 ≥55%——成品感一半在这里。
5. **默认运行中**：页面打开就是工作状态，导览是浮层邀请；导览之外有自由探索（分解/拖拽/自由开关），进度存本地、可链接分享。
6. **质量门**：六维验收（上线可访问/视觉质感/交互深度/内容完整度/细节真实性/演示就绪度），逐项有过线标准与一票否决项，证据以截图和实测为准。
7. **演示与部署**：60 秒演示（运行中全景 → 导览 → 搞坏它 → 修复 → 标题卡），段内断言防「点击落空」、响度 −14 LUFS 两遍法；部署到静态托管后用干净浏览器拉线上页核对。

## 使用

把整个目录放进你的 agent 的 skills 目录（或在任务中让 agent 先通读 `SKILL.md` 与 `QUALITY-GATE.md`），然后给它一个题目：

> 用 working-machine 给「<某个设备/元件>」做个说明：<一个问题>，待证明的事实是「<一句话>」。

agent 应按流程先交 BRIEF 与模型基线，再生成页面，过自查清单与质量门，最后交付可公开访问的链接与 60 秒演示。
